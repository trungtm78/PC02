# T1b HTTP contract — frozen for UI integration

All routes use `/api/v1` prefix and `{success:true,data:...}`. Actor comes only from authenticated request. Case reads require current Case read/scope/sensitivity; all mutations additionally require current writable parent and explicit governance capability. Flag OFF rejects new mutations. No seed publishes legal configuration.

Latest frozen additions: `GET /cases/:id/actions/capabilities?requestId=&asOf=YYYY-MM-DD&inspectionPurpose=` returns `{caseId,status,investigationPhase,configurationAsOf,actions:[{code,legacyId?,allowed,ready,reasons,requiredFields,ruleVersionIds}]}`. Allowed means current server authority/state/configuration permits drafting; ready requires the exact independently approved request and all verified source facts. Current configuration day is an evaluation clock and never supplies a legal decision date. Quarantined classification inspection requires explicit internal manage_access/read_sensitive, ordinary Case rights/scope, and recorded purpose; it permits only classification commands.

`CLASSIFY_SENSITIVITY` follows the same DRAFT/revision/approval workflow. Payload adds `{sensitivity:"NORMAL"|"RESTRICTED",inspectionPurpose,reason}` alongside the real decision facts. Purpose remains immutable through revisions. Execution changes dedicated and normalized legacy sensitivity only, retains prior labels/decision/actor/purpose in history, and preserves legal status/phase/dates. Independent review is required for tightening and downgrading.

Split adds mandatory `allocation:{subjects?,documents?,assets?,evidences?,fields?}`. The first four contain `{id,expectedUpdatedAt}` references; immutable assets use createdAt for that timestamp. Fields contain registered canonical132 or published custom keys. At least one concrete part is required. Server-owned `allocationSnapshot` freezes ownership, exact versions, source byte hashes/lineage, and field value hashes/clear/unknown state before approval; changes require revise/review. Source children remain attached to the source. The typed SPLIT relation retains the approved allocation and grants no implicit access. Child Case/UTDT type, tightened source sensitivity, and pinned field policy are preserved. UTDT additionally requires the published action's allowedCaseTypes to include UY_THAC_DIEU_TRA and new distinct `{soQuyetDinhUyThac,donViGiao,thoiHanUyThac,loaiUyThac,uyThacSourceDocumentId}`; old unique identities are never copied.

`CORRECT_DECISION` may revoke a relation using `{correctedDecisionId,relationId,expectedRelationRevision,reason}`. It must bind the active relation's original decision and authorize both parents. It appends a correction and increments/revokes the relation rather than deleting history. Packet relation pins become stale after this revision.

Source document ownership is checked by the shared evidence helper. A directly related document requires active typed relation plus independently authorized original owner and target Case; the server snapshot includes ownerCaseId/relationId/revision as well as bytes/version. Clients must omit server-owned sourceSnapshot/allocationSnapshot/utdtSourceSnapshot when revising requests.

Versioned `deadlineEffect` uses the exact configuration contract in [deadline-effect.md](deadline-effect.md). New restored/supplementary/reinvestigation phases require CALCULATE with confirmed actual anchors, verified source IDs, gravity/authority mappings and pinned calendar. Civil month/end-month/nonworking-day calculations record provenance in decision/event and update the Case deadline and system task atomically. Internal handoff never resets it. PRESERVE records retained legacy values as explicitly unverified; it never certifies a statutory deadline.

Field definitions may include immutable canonical `fieldPolicies:[{key,sensitivity,searchable?,exportable?}]`. Runtime schema adds server `{readable,writable}` flags; clients hide and omit forbidden native writes. Native columns, aliases, statistic values, opaque raw snapshots and nested custom stores share the same serializer. Search partitions schema/current grants and compiles only permitted fields; protected aggregate search indexes are excluded. REPRESENTATION_ONLY list grants search only id/code/name/status, while private filters require view grants. Global configuration/default schema/adoption remains INTERNAL-only even with accidental role capabilities; matching case-specific edits use current granted rights.

`GET /cases/governance/catalog` returns `{actions:[21 frozen entries],additionalActions:[VERIFY_PHASE,SPLIT_CASE,CORRECT_DECISION,LINK_RELATED,LINK_SOURCE],legalPublication}`. `GET /cases/:id/actions` returns `{requests,decisions}`.

`POST /cases/:id/actions`: `{requestKey,expectedUpdatedAt,actionCode,ruleVersionId,payload}` creates a DRAFT. `PATCH /cases/:id/actions/:requestId`: `{requestKey,expectedUpdatedAt,expectedAggregateUpdatedAt,expectedRevision,payload}` increments revision, returns DRAFT and clears approval. `POST .../submit` same version fields plus optional `reviewerId`; `POST .../review` plus required boolean `approve` and nonblank `note`; `POST .../execute` version fields. Mutation result requires refresh of current Case updatedAt before next command. Request state DRAFT → SUBMITTED → APPROVED/REJECTED → EXECUTED; revise permitted before execution and invalidates approval. Author cannot review.

Payload `decision`: `{type,number,date,effectiveDate,issuer,signatory,legalBasis,sourceDocumentId}` with complete actual YYYY-MM-DD dates and owned source document. Transfers require `destinationAgency`; merge/related require `targetCaseId`; expiry requires `expirationEvaluation:"EXPIRED_VERIFIED"` and discontinuation requires an already executed expiry evaluation. `VERIFY_PHASE` requires `verifiedPhase` and an unknown current investigation phase. `SPLIT_CASE` requires `newCase:{name,crime?,assignedTeamId,allocationBasis}`; it allocates the shared CASE counter, preserves source children/history and creates typed provenance. `CORRECT_DECISION` requires `correctedDecisionId` and appends a decision. `LINK_SOURCE` requires `{sourceType:"INCIDENT"|"PETITION",sourceId,sourceUpdatedAt}` and links existing authorized sources explicitly.

`GET/POST /cases/governance/rules`, `PATCH .../rules/:id`, `POST .../:id/validate|review|publish`. Draft body `{code,requestKey,definition,effectiveFrom,effectiveTo?}`; revise requires `{expectedUpdatedAt,expectedRevision,definition,effectiveFrom,effectiveTo?}`; transitions require expectedUpdatedAt/expectedRevision. Definition `{actions:[{code,legalSources:[{id?,instrument,provision,url,authority,effectiveFrom,effectiveTo?}],conditions?,requiredFields?,allowedCaseTypes?,deadlineEffect?}]}`. Deadline configuration uses the versioned PRESERVE/CALCULATE contract above and in deadline-effect.md; calculated sources reference explicit source IDs. Allowed declarative conditions `{all:[...]}`, `{any:[...]}` or `{path:"case.*"|"payload.*",op:"eq"|"in"|"exists",value}`. Independent review and publication, exact approved hash/revision, published revisions immutable. Sources are selected-reference evidence, not statutory certification.

`GET/POST /cases/governance/field-definitions`, `PATCH .../:id`, `POST .../:id/validate|review|publish` same lifecycle with definition `{fields:[{key,label,type,required,options?,sensitivity?,tab?}]}`. Keys must match custom_ prefix; six types text/textarea/number/boolean/date/select; options strings; sensitivity NORMAL/RESTRICTED.

`GET /cases/governance/field-schema` returns latest published `default` schema with empty values for INTERNAL actors. `GET /cases/:id/governance/field-schema` returns **pinned** schema or `{success:true,data:null}` for unpinned legacy Case. Data shape `{id,revision,status:"PUBLISHED",definition:{fields:[...],fieldPolicies?:[{key,sensitivity,searchable?,exportable?,readable,writable}]},values:{...authorized metadata._customFields}}`. Historical published/superseded pins remain readable. Sensitive fields/values are filtered server-side. `POST /cases/:id/governance/field-schema`: `{requestKey,expectedUpdatedAt,fieldDefinitionVersionId?,values:{custom_key:typedValue}}`; explicitly adopts published version and validates typed values, preserving canonical metadata and unknown legacy custom history. Ordinary Case create/update accepts metadata._customFields in the ONE CaseForm save through the same transaction-bound validation; the server pins its FK and rejects client Case FK authority. Omitted hidden values remain preserved. UI must omit native fields whose policy reports writable:false.

`GET /cases/governance/dashboard`: `{clock,buckets:[{key,count,link}]}`. `GET /cases/governance/queues/:key?clock=<ISO>`: `{clock,key,items,total}`. Keys pending/assigned/missing/review/due/overdue; same current authorized base/formulas. Assigned means current actor investigator; missing means blank Case name or DANG_DIEU_TRA with unknown phase/missing initiation date. Due means active Case current deadline in [clock,clock+7days], overdue strictly before clock; completed/discontinued/transferred/merged states excluded. Review means SUBMITTED action exists. List/count/export consumers must AND the returned queue IDs into their existing authorized query at that clock.

`GET /cases/governance/tasks` returns authorized task rows. `POST /cases/:id/governance/tasks` and `PATCH .../:taskId` body `{requestKey,expectedUpdatedAt,expectedAggregateUpdatedAt? (required PATCH),type,sourceId,assigneeId?,status?,dueAt?,payload}`; status OPEN/IN_PROGRESS/COMPLETED/CANCELLED; active authorized writable assignee. Existing task identity type/sourceId immutable; parent/request aggregate CAS and current permissions rechecked. Internal notifications only, no external sending.

`GET /cases/:id/relations` returns typed rows with `{sourceCase:{id,name,caseCode},targetCase:{id,name,caseCode}}` only when both parents currently readable. `POST /cases/:id/relations` body `{requestKey,expectedUpdatedAt,targetCaseId,decisionId,type:"RELATED"}` requires executed LINK_RELATED decision authorizing exact target. Merge/split run through approved action execution. Cycles/self-target/hidden/unwritable targets rejected; source children/history untouched.

Private `CaseOutboxWorker` polls internal committed rows, claims expiring 60-second lease, transactionally rechecks recipient ACL and creates deterministic internal Notification+DELIVERED marker. Revoked recipient suppressed; failures exponential retry up to10 then DEAD_LETTER. No outward email/push/partner APIs invoked. This document is an interface snapshot; full T5 DB/UAT/review gates remain outstanding.
