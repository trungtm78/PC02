Validate document.caseId or explicit authorized relation, never user-supplied unrestricted file paths. Retention is preserve-until-approved when no published policy; eligibility does not purge. Permission conditions accepted only in validated declarative schema with own-property safe paths, no arbitrary code.

Evidence routes under `:id/evidence-governance`: assets/register, asset/version/derivative/verify, custody append/history, packets create/revise/submit/review/export/revoke, hold add/release, representation grants add/revoke, retention draft/publish/eligibility/disposition. Require requestKey+expected aggregate version for mutations; legal execution requires exact approved request revision/hash and real decision civil dates. Server-owned actor/status/hash/version; no client authority flags. UI uses returned capabilities/readiness reasons rather than inferring legal permission.

General Case PUT remains basic information editing. Semantic status changes route through governed commands when feature enabled; legacy adapters validate identical requirements, never bypass. Pending guard also applies common parent-case write helper/child services and bulk. CaseStatusHistory and CASE_STATUS_CHANGED audit move into parent mutation transaction even when flag OFF. Existing child create must not claim Case legal progress by itself. Explicit source action replaces tab-triggered automatic Incident generation; compatibility response remains but no phantom source creation.

Published rules contain stable codes, legacy id/state/target, broad status+phase predicates, required fields, legal source/version/effective interval, capability, deadline algorithm IDs and result type.21 mappings immutable in catalog; additional verification/split/correction actions separately registered. Expiry records evaluation facts. No complete date→readiness false. No blanket missing-data waiver based on createdAt. Existing current deadline formulas retained until per-rule verified publication; receipt never resets them.

Field metadata registry includes canonical ownership/aliases, types/labels/storage/access/search/export and explicit-clear semantics. CaseForm/Detail/list/export use same canonical accessor; metadata fallback only for unmapped legacy values, explicit canonical clears retain tombstone/provenance.10-tab editable/read-only renderer shared; preserve specialized detail tabs and layouts. Dynamic published field definitions validated/version pinned and unknown legacy preserved.

Action execution transaction: lock/validate source and targets, active authority and scopes, expected Case/request versions, approved hash/rule/effective dates; write decision, Case mutation/phase/relation, histories+audit+internal outbox. Unique retries same content return original; differing content conflict409. Outbox worker leases rows, uses internal Notification idempotency, rechecks recipient visibility, marks delivered atomically; no external email/partner integration activated by tests.

Disclosure approval freezes exact item document version/hash/redaction/lineage, recipient and expiry. Export rechecks item ownership/grants/holds/visibility, generates versioned manifest and byte hashes with offline verification against trusted approved manifest hash. Changing content invalidates approval; delta packets explicit. Holds protect all destructive entrypoints. History corrections append; legal signed decision authenticity remains externally verified, hash alone is not authenticity.

Operational gate: Case governance flag defaultOFF, no inferred legacy events or direct production activation.
